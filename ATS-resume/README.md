# ResumeIQ: AI Resume and ATS Analyzer

ResumeIQ compares a PDF resume with a job description and produces an ATS-style score (0 to 100), skills match,
matching / partial / missing skills, keyword gaps, section-by-section resume quality ratings, job fit analysis, and a
prioritized list of recommendations. The analysis is generated by an AI model through **OpenRouter**.

## Tech stack

- React 18 and Vite (frontend), Tailwind CSS, Lucide icons
- PDF.js (`pdfjs-dist`) for reading PDFs in the browser
- Vercel Serverless Function (`api/analyze.js`) calling the OpenRouter Chat Completions API
- Vercel for hosting, GitHub for source control

## How it works

1. The browser reads the PDF with PDF.js and extracts the text. The PDF file is never uploaded.
2. The browser sends the extracted resume text and job description to `POST /api/analyze`.
3. The serverless function validates the input, calls OpenRouter with the server-side API key, parses the JSON reply,
   checks it against the scoring rubric and response structure, and returns the report.
4. Nothing is written to a database or file. The API key never reaches the browser.

## Environment variables

| Name | Required | Example | Purpose |
| --- | --- | --- | --- |
| `OPENROUTER_API_KEY` | **Yes** | `sk-or-v1-...` | Your OpenRouter API key. Server-side only. |
| `OPENROUTER_MODEL` | No | `openrouter/free` | Any OpenRouter model ID. If empty, `openrouter/free` is used. |

Rules:

- Use exactly these names. Do **not** add a `VITE_` prefix. That would expose the key in the browser bundle.
- Your `.env.example` file contains:

  ```
  OPENROUTER_API_KEY=
  OPENROUTER_MODEL=openrouter/free
  ```

## Getting an OpenRouter API key

1. Go to https://openrouter.ai and sign in or create an account.
2. Open https://openrouter.ai/keys and choose **Create key**. Give it a name such as `resumeiq`.
3. Copy the key (it starts with `sk-or-`). OpenRouter shows it only once, so save it somewhere safe.
4. Keep the key private. Do not paste it into code, screenshots, issues, or GitHub.

Free models need no credits, but OpenRouter limits how many requests free models accept per minute and per day.
Adding a small amount of credit to your account raises those limits and avoids most "busy" messages.

### Choosing a model

The default, `openrouter/free`, is OpenRouter's router that selects from currently available free models, so the
app keeps working as individual free models come and go. To pin a specific model instead, set `OPENROUTER_MODEL` to
any model ID from https://openrouter.ai/models (for example `meta-llama/llama-3.3-70b-instruct:free`). Choose a model
that supports long context and JSON output. If a model is unavailable, the app shows a message that asks the site
owner to check `OPENROUTER_MODEL`.

## Configure the variables in Vercel

1. Open your project on https://vercel.com and go to **Settings > Environment Variables**.
2. Add `OPENROUTER_API_KEY` with your key. Select **Production** (and **Preview** if you want preview deployments to work).
3. Optionally add `OPENROUTER_MODEL` with the model ID you chose.
4. Save. Environment variables apply only to new deployments, so go to **Deployments**, open the latest one, and choose
   **Redeploy**.

## Deploy the project

### Option A: from GitHub (recommended)

1. Push this project to a GitHub repository. Include the hidden `.gitignore` and `.env.example` files. Do **not**
   commit `node_modules`, `dist`, or any `.env` file. The `.gitignore` already excludes them.
2. On https://vercel.com choose **Add New... > Project**, then **Import** the repository.
3. **Root Directory:** if this project is inside a folder of the repository, such as `resumeiq-github-repo/` in the
   `ATS` repository, click **Edit** next to Root Directory and select that folder. The `package.json`, `api/`, and
   `vercel.json` must be at the root directory Vercel uses. If the project is at the repository root, keep the default.
4. Vercel detects Vite. Keep the defaults: Install Command `npm install`, Build Command `npm run build`, Output
   Directory `dist`. These are also set in `vercel.json`.
5. Add the environment variables from the section above **before** the first deploy, then choose **Deploy**.
6. Open the generated URL. Upload a text-based PDF resume, paste a job description, and choose **Analyze resume**.

Every push to the connected branch triggers a new deployment automatically.

### Option B: Vercel CLI

```bash
npm install -g vercel
vercel login
vercel --prod
```

Add the variables with `vercel env add OPENROUTER_API_KEY production`, then deploy again.

## Local development

You need Node.js 18.18 or newer.

```bash
npm install
cp .env.example .env.local      # then put your key in .env.local
npx vercel dev                  # runs the frontend and /api/analyze together
```

`npx vercel dev` is required for the analysis to work locally, because the API runs as a Vercel function. Plain
`npm run dev` serves only the frontend. `.env.local` is ignored by Git.

Checks:

```bash
npm test                 # API error handling, JSON parsing, retries, and dashboard contract (no network or key needed)
npm run build            # production build
npm run preview          # serve the production build locally
OPENROUTER_API_KEY=sk-or-... npm run check:openrouter   # live call to OpenRouter; validates the real response
```

`npm run check:openrouter` sends one sample resume to OpenRouter and validates the reply. It prints the score and
section count, never the resume text or your key. Run it once after setting the key to confirm the model returns
the expected structure.

## Project structure

```
api/analyze.js            Vercel serverless endpoint: POST /api/analyze
lib/limits.js             Input size limits (shared by browser and server)
lib/rubric.js             Scoring rubric (categories and maximum points)
lib/prompt.js             System prompt and required JSON structure for the model
lib/openrouter.js         OpenRouter client: timeouts, error mapping, JSON mode fallback
lib/runAnalysis.js        Calls the model, parses JSON, validates, retries once when safe
lib/validateAnalysis.js   Checks and normalizes the model output; recomputes the score
tests/                    npm test: API behavior with a mocked OpenRouter, and the dashboard contract
scripts/                  Live OpenRouter check (npm run check:openrouter)
src/components/           Navbar, footer, logo, upload zone, job description input, progress, score ring, dashboard
src/pages/                Home page and analyzer page
src/services/             Browser client for /api/analyze
src/utils/                PDF validation and text extraction
public/                   Favicon
vercel.json               Vercel build and function settings (60 second limit for the API)
.env.example              Environment variable template
```

## Limits and validation

| Item | Limit |
| --- | --- |
| PDF file size | 5 MB |
| PDF pages | 15 |
| Extracted resume text | 100 to 30,000 characters |
| Job description | 80 to 8,000 characters |

Scanned or image-only PDFs have no selectable text and cannot be analyzed. Export a text-based PDF from your word
processor instead.

## Security and privacy

- The OpenRouter key is read only from server environment variables and is sent only to `openrouter.ai`.
- Resume text and job descriptions are treated as untrusted data. The prompt tells the model to ignore instructions
  inside them, and tags in the content are stripped before sending.
- The server never logs resume or job description content. Logs contain only an error code, HTTP status, and model name.
- ResumeIQ does not store resumes or extracted text. The text is sent to OpenRouter and the model provider you
  selected to produce the report. Review OpenRouter's and the provider's data policies before using real personal data.
- Scores are estimates from a published rubric. They do not guarantee selection or reflect any employer's ATS.

## Troubleshooting

| Message | Fix |
| --- | --- |
| "The server is not configured yet" | Add `OPENROUTER_API_KEY` in Vercel and redeploy. |
| "The server could not authenticate with OpenRouter" | The key is wrong, revoked, or copied with extra characters. Create a new key and update Vercel. |
| "The configured AI model is unavailable" | Set `OPENROUTER_MODEL` to a current model ID (or `openrouter/free`), then redeploy. |
| "The OpenRouter account has no credits left" | Add credits or choose a different model. |
| "The AI service is busy or its usage limit was reached" | Free-model rate limit. Wait a minute, try again later, or add credits. |
| "The analysis took too long" | Try again. If it keeps happening, choose a faster model in `OPENROUTER_MODEL`. |
| "We could not find enough readable text" | The PDF is scanned or image-only. Export a text-based PDF. |
| "The analysis service was not found" locally | Use `npx vercel dev` instead of `npm run dev`. |
